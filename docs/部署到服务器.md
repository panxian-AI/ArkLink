# 部署到服务器：长期前台运行版

> 一句话：**把 ArkLink 直接装在一台小服务器上，浏览器打开就是一个能长期操作 QQ 的前台**。
> 不需要 VirtualBox、不需要虚拟机、不需要桌面环境——服务器本机就是运行环境。

## 什么时候选这条路

| | 本机 + 虚拟环境（`arklink env`） | 服务器直装（本文） |
|---|---|---|
| 适合 | 自己的 Windows 电脑旁边挂一个 QQ | 7×24 无人值守，团队/上层程序共用 |
| 需要装 | VirtualBox + Ubuntu 镜像（约 3.4GB） | 什么都不用装，一条脚本全搞定 |
| 访问 | 宿主机 `127.0.0.1:6800` | 任何浏览器打开 `http://<服务器IP>:6800` |
| 宕机影响 | 你关机它就停 | 服务器不关就一直跑，重启自恢复 |

## 需要什么

- 一台小服务器：**2 核 / 2GB 内存 / 8GB 磁盘**就够（QQ Linux + Xvfb + 两个 Python 服务）；
- 系统：Ubuntu 22.04 / 24.04 或 Debian 12（脚本会拒绝其它发行版并告诉你为什么）；
- 一个 QQ Linux 的 deb 安装包（从 <https://im.qq.com/linuxqq/index.shtml> 下载，放到服务器 `/tmp/`）。

> **关于"虚拟桌面"**：服务器上不需要 VirtualBox 那层虚拟机。唯一保留的是
> **Xvfb 无头虚拟屏**——QQ Linux 是图形程序，得给它一块"看不见的屏幕"才能登录和收发。
> 它只占几 MB 内存，不是桌面环境；按键注入（xdotool）也依赖它。

## 一条命令安装

把仓库推到服务器（或 `git clone`），然后：

```bash
sudo bash tools/setup_server.sh --source /path/to/ArkLink --qq-deb /tmp/QQ_xxx_amd64.deb
```

脚本会自动完成：

1. 装依赖（Xvfb、openbox、xdotool、中文字体——字体没装上会直接报错退出，因为坐标会错）；
2. 装 QQ、建 Python 虚拟环境装 ArkLink；
3. 生成两把密钥：`/etc/arklink/webui.token`（网页登录口令）、`/etc/arklink/api.token`（API token），权限 600；
4. 写三个 systemd 服务并开机自启；
5. 自检并打印 token 与下一步。

只想本机访问、不开公网端口：加 `--bind-local`，WebUI/API 只听 `127.0.0.1`，用 SSH 隧道访问（见下文安全清单）。

## "长期前台运行"是靠什么保证的

三层保障，缺一不可：

1. **systemd**：`arklink-qq` / `arklink` / `arklink-api` 三个服务开机自启、崩溃 5 秒后自动重启；
2. **QQ 看护（watchdog）**：`/opt/arklink/qq-watchdog.sh` 每 15 秒巡检一次，Xvfb / openbox / QQ
   谁不在就拉谁；QQ 崩溃重启有 60 秒防抖，避免反复闪退刷日志；
3. **登录态持久化**：QQ 窗口在线时每 24 小时自动备份 `~/.config/QQ` 到
   `/var/lib/arklink/qq-login.tgz`；QQ 不在了（比如服务器重启后）自动还原——**扫一次码，长期有效**。

看护日志：`journalctl -u arklink-qq -f`（能看到"已拉起 QQ / 登录态已备份"这类记录）。

## 首次登录（只此一次）

QQ 要扫码登录一次。脚本不把 VNC 端口暴露到公网，走 SSH 隧道：

```bash
# 服务器上：
apt-get install -y x11vnc
x11vnc -display :99 -rfbport 5901 -passwd "<webui.token 的内容>" -forever &

# 你自己的电脑上：
ssh -L 5901:127.0.0.1:5901 root@<服务器IP>
# 然后 VNC 客户端连 127.0.0.1:5901，扫码
```

扫完码看护服务会自动备份登录态，之后服务器重启都免扫码。

## 浏览器前台操作

打开 `http://<服务器IP>:6800`，输入 `/etc/arklink/webui.token` 里的口令登录。
能看状态、发消息、查记录、做体检、管白名单——和本机版是同一个页面。

## 上层程序接 API

地址 `http://<服务器IP>:6900`，Bearer token 用 `/etc/arklink/api.token`。
接口清单、SSE 收消息、能力矩阵见 [接入上层.md](接入上层.md)。

## 安全清单（对外服务器必做）

- 云控制台**安全组**只放行 `6800` / `6900`；5901（VNC）永远只走 SSH 隧道，不开公网；
- 或者最保守：不开任何端口，全走隧道
  `ssh -L 6800:127.0.0.1:6800 -L 6900:127.0.0.1:6900 root@<服务器IP>`，
  并用 `--bind-local` 重装让服务只听 `127.0.0.1`；
- 两把 token 不要外发；怀疑泄露就删掉 `/etc/arklink/*.token` 重跑脚本（会重新生成并重启服务）；
- 出厂白名单是空的（默认拒绝），先 `arklink peers uin <你的QQ号>` / `peers allow` 再发消息。

## 常见问题

**QQ 掉线了？** 看护会把 QQ 拉起来，登录态在备份里，通常几十秒内自动恢复。
超过一分钟没恢复再看 `/tmp/qq.log`。

**内存不够 / 被杀？** 2GB 是底线。`systemctl status arklink-qq` 里看是否 OOM；
不够就升配，或把服务器上其它东西挪走。

**想升级 QQ？** 放新 deb 到 `/tmp/`，`apt-get install -y /tmp/QQ_new.deb`，
看护会自动把新版拉起来，登录态不受影响。

**迁移到另一台服务器？** 拷走 `/var/lib/arklink/qq-login.tgz` + `/etc/arklink/*.token`，
新机器重跑安装脚本后把备份放回 `/var/lib/arklink/`，重启 `arklink-qq` 即可，不用重新扫码。
