## 六、与 ArkBot 的联动（上篇 / 下篇）

ArkBot 是业务框架，ArkLink 是协议外挂层；一个管「机器人做什么」，一个管「怎么连上 QQ」。
依赖是**单向、运行时**的：ArkBot 没有一行 `import arklink`，靠 entry point
`arkbot.adapters` 发现外部适配器；ArkLink 只在真正交付事件时才导入 `arkbot.event`。
因此两个仓库都能单独安装、单独使用，合起来才是完整形态。

**叙事衔接**

- 上篇 ArkBot 第 3 页那枚「＋预留位 · 下一个协议」，答案就是 ArkLink 的通道层；
  ArkBot README 架构图里写的「预留 native-qq：直连 NTQQ 的接口位」，正是 `ntqq-hook` / `ntqq-client` / `x11` 在做的事。
- 本片第 4 页「按契约写一个适配器，不用改上层」，契约由 ArkBot 定义；`1404` 的语义也是框架约定。
- 本片第 6 页「OneBot 11 老生态零改动」，回接的是 ArkBot 对外扮演 OneBot 服务端的兼容层。
