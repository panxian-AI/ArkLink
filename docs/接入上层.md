# 接上层：ArkLink 是一个 bot，不是一堆脚本

你只需要记住三个东西：**Bot（收消息 → 你的函数）、Client（发消息 / 查询）、HTTP API（跨语言）**。
上层做什么都行——关键词回复、接大模型、定时播报、工单流转——只要它能调用一个函数或发一个 HTTP 请求。

```
你的业务 / LLM / 定时任务
        │  写一个函数：收到消息 → 返回要回的话
        ▼
   arklink（bot 运行时）        ← 常驻，负责：收发、白名单、去重、续传、重连
        │
        ▼
   QQ（官方客户端，UI 通道 / 进程内通道）
```

---

## 一、三分钟接上（Python）

```bash
arklink serve api                # 窗口 1：起服务（会打印地址和 token，也写进 ~/.arklink/api.json）
arklink bot new mybot.py         # 窗口 2：生成模板
arklink bot run mybot.py         # 跑起来
```

`mybot.py` 就是全部：

```python
from arklink.bot import Bot

bot = Bot()

@bot.on_message
def echo(msg):
    return f"收到：{msg['text']}"     # 返回字符串 = 自动回复；返回 None = 不回
```

`Bot` 帮你处理了：SSE 断线自动重连、按 `seq` 续传（不丢不重）、群聊/私聊的差异、
自己发的消息不回灌（防自激）、handler 抛异常不中断收消息。

**出问题先跑 `arklink bot check`**，它逐项检查并给出下一步：

```
  ✅ 服务：http://127.0.0.1:6900（v0.12.0）
  ✅ 鉴权：token 有效
  ✅ 发送账号：已配置 123456789
  ✅ 收件人：已配置 备注名
  ✅ 发送引擎：host 可用
```

## 二、三种接法，选一个

| 接法 | 适合谁 | 怎么用 | 现状 |
|---|---|---|---|
| **Python 回调** | 自己的脚本、LLM agent | `arklink bot new` + `@bot.on_message` | ✅ 可用 |
| **HTTP + SSE** | 任何语言（Node/Go/Java/…）、跨机器 | `GET /api/v1/stream` 收，`POST /api/v1/send` 发 | ✅ 可用 |
| **OneBot 11** | NoneBot2 / Koishi / 现成 bot 框架 | `arklink serve onebot --type ntqq-hook` | ⚠️ 需要注入通道（收消息 hook 未完成） |

前两种是**同一套后端**，只是调用方式不同；OneBot 那套是给现成框架用的适配层。

## 三、能力矩阵（先说清能做什么）

同类 bot 的事，这里逐条列出来。**没打勾的，接口会返回 1404 并写明缺什么**，
不会假装成功、也不会含糊说「不支持」。

| 能力 | 能做 | 说明 |
|---|---|---|
| 发文本（私聊 / 群聊） | ✅ | UI 通道：搜索会话 → 输入 → 回车 |
| 一次发多个对象 / 多条 | ✅ | 顺序执行，结果一一对应，中间失败不影响后续 |
| 收消息（总线 + SSE） | ✅ | 采集器推进来就走这条路；hook 通道就绪后自动进 |
| 发送白名单 | ✅ | 账号、收件人、群聊三道闸，写在代码里，任何入口都不绕过 |
| 好友 / 群列表 | ✅ | 来自 `peers.json`（`arklink roster --save-peers` 生成） |
| 发图片 / 发文件 | ✅ | **只能发本机已有文件**：放进剪贴板再粘贴，URL 要先落盘 |
| 表情 | ❌ | 剪贴板粘不出小黄脸，需要进程内直发 |
| @ 某人 / 引用回复 | ❌ | UI 只能打出「@名字」文字，不是真 @ |
| 撤回消息 | ❌ | 需要按消息 id 操作客户端 |
| 拉历史消息 | ❌ | 本地消息库加密（`file is not a database`），UI 也拿不到 |
| 群禁言 / 踢人 | ❌ | 需要群管理接口 |

随时用接口查，不靠文档对齐：

```bash
curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:6900/api/v1/capabilities
```

```json
{"channel": "host",
 "ok": ["send.text", "send.multi", "receive.message", "policy", "image", "file", "roster"],
 "missing": ["face", "at", "reply", "recall", "history", "group.mute", "group.kick"],
 "items": [{"key": "image", "label": "发图片", "ok": true,
            "reason": "只能发本机已有的文件，URL 要先下载到磁盘",
            "need": ""}]}
```

> 上层的正确写法：先读 `capabilities`，有的功能就用，没有的走降级（比如图片改发文字链接），
> 而不是撞一次 1404 才知道。
>
> 附件注意三件事：`file` 必须是**本机绝对路径**；`image`/`file` 段里给 URL 会被 1404；
> 一条最多 10 个附件。

## 四、接口清单

所有接口都在 `/api/v1` 下，鉴权用 `Authorization: Bearer <token>`（也认 `?token=`）。

| 方法 | 路径 | 作用 | 主要参数 |
|---|---|---|---|
| GET | `/health` | 存活与版本（**不需要 token**） | — |
| GET | `/status` | 引擎、可用性、策略、队列、总线统计 | — |
| GET | `/capabilities` | 能力矩阵 | — |
| POST | `/send` | 发消息 | `to` / `targets`、`text` 或 `message`、`dry_run`、`group`、`echo` |
| GET | `/messages` | 取收件箱 | `since`（seq）、`limit` |
| GET | `/stream` | 订阅新消息（SSE） | `since` |
| POST | `/inbound` | 采集器推消息进来 | 消息对象，或 `{"items": [...]}` |
| GET | `/sends` | 发送记录 | `limit` |
| GET | `/self` | 当前配置的账号 | — |
| GET | `/friends` `/groups` | 好友 / 群列表 | — |
| GET/POST | `/policy` | 看/改白名单 | `action`: `allow` / `deny` / `reset`、`values`、`group` |
| GET | `/history` | 历史消息 | ❌ 501，带 `need` |
| POST | `/recall` `/group/mute` `/group/kick` | 撤回 / 禁言 / 踢人 | ❌ 1404，带 `need` |

### 发一条

```bash
curl -X POST http://127.0.0.1:6900/api/v1/send \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"to":"备注名","text":"你好"}'
```

多对象 × 多条（顺序执行，`items` 与入参一一对应）：

```json
{"to": ["备注名", "某群"], "text": ["第一条", "第二条"], "group": true}
```

结构化消息（段数组，OneBot 风格；不支持的段会带 `need` 返回 1404）：

```json
{"to": "备注名", "message": [{"type": "text", "data": {"text": "看图："}},
                            {"type": "image", "data": {"file": "/tmp/a.png"}}]}
```

### 收消息

```bash
curl -N -H "Authorization: Bearer $TOKEN" "http://127.0.0.1:6900/api/v1/stream?since=0"
```

```
event: hello
data: {"last_seq": 12, "since": 0}

event: message
data: {"seq": 13, "id": "7xxxx", "ts": 1794490320.7, "time": "21:32:00",
       "chat_type": 1, "peer_uid": "备注名", "sender_uid": "123456789",
       "sender_name": "备注名", "text": "在吗", "source": "hook"}
```

断线重连带 `since=<最后一条的 seq>`，不会重复、不会漏。

### 消息对象字段

| 字段 | 含义 |
|---|---|
| `seq` | 服务端单调递增序号，续传就靠它 |
| `id` | 平台消息 id（采集器给了才有） |
| `chat_type` | `1` 私聊、`2` 群聊 |
| `peer_uid` | 会话对象（群号 / 对方 uid） |
| `peer_name` | 群名 / 备注 |
| `sender_uid` / `sender_name` | 谁发的 |
| `text` | 纯文本（段数组已压平，图片变 `[图片]`，@ 变 `@QQ`） |
| `source` | 从哪个采集器来的 |

## 五、在虚拟机里后台跑（不占你的桌面）

```bash
arklink env up                   # 起虚拟机（无头）
arklink env push                 # 推代码，guest 里自动装 QQ / Xvfb / Arklink / systemd 服务
arklink env token                # 取 API 地址 + token
```

guest 里会注册两个 systemd 服务，开机自启、挂了自动重启：

| 服务 | 端口（映射到宿主 127.0.0.1） | 作用 |
|---|---|---|
| `arklink.service` | 6800 | WebUI 控制台 + Xvfb + QQ |
| `arklink-api.service` | 6900 | **bot 接口**（`serve api --engine x11`） |

所以宿主机上直接：

```bash
arklink bot check                # 会自动读 ~/.arklink/api.json
arklink bot run mybot.py
curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:6900/api/v1/status
```

端口只绑 `127.0.0.1`，局域网里别人连不上；要给别人用就开 SSH 隧道，别直接把端口开到公网。

## 六、明确提示：错误码与 `need`

| 情况 | HTTP | `code` | 你会看到 |
|---|---|---|---|
| 没带 token | 401 | 401 | `需要 token` |
| 参数缺失 | 400 | 1400 | `缺少收件人（to / targets）` / `缺少内容（text / message）` |
| 不在白名单 | 400 | 1404 | `本地映射里没有「x」，先 arklink peers allow x` |
| 没配账号 | 400 | 1403 | `发送账号白名单是空的（出厂默认）：先 arklink peers uin <你的QQ号>` |
| 通道做不到 | 400 | 1404 | `msg` 说原因，`need` 说缺什么 |
| 历史消息 | 501 | 1404 | `本地消息库加密…` + `need` |

约定：**`need` 永远是可执行的一句话**。看到它就能知道下一步是换通道、改配置，还是放弃这个功能。

## 七、常见问题

**Q：第一次跑，什么都没配，会不会乱发？**
不会。出厂白名单是空的，空 = 全拒。先 `arklink peers uin <你的QQ号>`、`arklink peers allow <备注>`。

**Q：`bot run` 会不会把历史消息全部回复一遍？**
不会。默认从「当前最新」开始；要回放从 `--since 0`。

**Q：handler 里能不能做耗时操作（调模型、查库）？**
可以，但一条一条串行处理。要并发就自己丢线程池——注意同一会话的消息顺序会乱。

**Q：上层是 Node / Go，怎么办？**
用 HTTP + SSE，不用装 Python 包。`GET /stream` 是标准 SSE，任何语言的 HTTP 客户端都能读。

**Q：能不能多个 bot 同时接？**
可以，每个 `arklink bot run` 独立订阅同一条流（总线支持多订阅者），但都受同一份白名单约束。

**Q：收消息现在真的能收到 QQ 的消息吗？**
现在收的是「推进总线的东西」：`/api/v1/inbound`（任何采集器）或 hook 通道。
QQ 客户端内的消息分发 hook（DLL 的 `AttachMessageHooks`）还没实现——这是 1.0 的唯一硬缺口，
补上之后这条路不用改任何接口，消息会自己进来。
